## 1. Что такое эмбеддинг

**Векторный эмбеддинг (vector embedding)** — плотный (dense) список вещественных чисел, представляющий объект (слово, предложение, документ, изображение, товар) в векторном пространстве (vector space).

- **Плотный** — потому что почти каждый элемент вектора несёт нагрузку (в отличие от one-hot, где один ненулевой элемент).
- Семантически близкие объекты располагаются рядом в пространстве: «кот», «собака», «лев» — один кластер; «машина», «грузовик» — другой.
- **Расстояние в пространстве = мера сходства по смыслу.**
- Эмбеддинг — это **«сжатие с потерями» (lossy compression)**: из высокоразмерного пространства данных в компактное пространство; отбрасывается форма (стиль, конкретные слова, длина), остаётся смысл. Исходный текст из вектора восстановить нельзя.
- Эмбеддинг — не магия и не человекочитаем: это числовой «отпечаток», выученный из статистики обучающих данных; качество ограничено качеством модели.

### One-hot encoding (унитарное кодирование) — что было до эмбеддингов

- Каждому слову словаря — своя позиция: 1 на своей позиции, 0 везде. Словарь из 100 000 слов → вектор длины 100 000, почти все нули (**разреженный / sparse**).
- Скалярное произведение любых двух разных one-hot векторов = 0 → косинусное сходство любой пары = 0 → **все слова равноудалены, семантики нет**. «Кот» не ближе к «собаке», чем к «машине».

### Вектор ≠ эмбеддинг

- **Вектор** — просто массив чисел (математический объект).
- **Эмбеддинг** — вектор, который структурно и осмысленно представляет данные (несёт семантику).
- **Каждый эмбеддинг — вектор, но не каждый вектор — эмбеддинг.** One-hot вектор — пример вектора без семантики, т.е. не эмбеддинг.

### Эмбеддинг ≠ индексация

- **Эмбеддинг** — процесс превращения сырых данных в векторы.
- **Индексация (indexing)** — построение структуры данных поверх векторов для быстрого поиска (HNSW — это индекс).
- Однострочник: *эмбеддинг создаёт вектор, индекс делает поиск по векторам быстрым.*

## 2. Размерность вектора (768 / 1536 / 3072)

- **Размерность = длина плотного списка чисел.** Свойство конкретной модели, не универсальная константа.
- Размерность задаётся **эмбеддинг-слоем (embedding layer)** — числом нейронов в нём.
  - ⚠️ Не путать: размерность слоя ≠ размерность финального вектора предложения (после пулинга).
- Примеры: 768 — BERT-подобные модели; 1536 — text-embedding-3-small; 3072 — text-embedding-3-large. Но бывают и маленькие: Airbnb — 32 измерения.
- Больше измерений → тоньше различение смыслов, но дороже хранение и вычисления. Вектор 1536 в float32 ≈ 6 КБ (1536 × 4 байта); 100 млн векторов → сотни гигабайт.

## 3. Почему близкие тексты → близкие векторы

Полная цепочка (для контрольной точки — без «нейросеть как-то кодирует»):

1. **Дистрибутивная гипотеза (distributional hypothesis)** — утверждение о языке: слова, употребляемые в похожих контекстах, имеют похожие значения.
2. **Обучение представлений (representation learning):** модель учится отображать высокоразмерные данные в компактное пространство, решая конкретную задачу (предсказать контекст, тональность, следующее слово).
3. Старт: веса эмбеддинг-слоя **случайны**, первоначальные векторы бессмысленны.
4. **Обратное распространение ошибки (backpropagation)** штрафует за ошибки предсказания и итеративно подкручивает веса.
5. Слова/тексты, **взаимозаменимые для задачи обучения**, получают похожие векторы. Семантика вырастает из задачи, а не задаётся вручную.

**Вывод: задача обучения формирует пространство эмбеддингов.** Модель, обученная на отзывах, хорошо различает «восторг/ужас», но может плохо различать юридические термины.

### Модель = пространство

- Векторы от **разных моделей несравнимы**, даже при одинаковой размерности: каждая модель строит свою систему координат (измерение №42 у разных моделей «значит» разное).
- **Сменил модель → перегенерируй эмбеддинги всего корпуса.**

### Re-embedding vs re-training (важно, не путать!)

- **Re-embedding (перегенерация эмбеддингов):** модель не трогаем; прогоняем все документы через (новую) обученную модель заново, записываем новые векторы. **Меняем данные, не модель.** Требуется при смене модели.
- **Re-training / fine-tuning (дообучение):** меняем **саму модель** — веса подкручиваются через backpropagation на новых данных (например, юридических текстах). **Меняем модель, не данные.**
- После дообучения пространство модели тоже меняется → за re-training обычно следует re-embedding.
- Прогон новых документов через существующую модель без изменения весов — это просто embedding новых данных, НЕ re-training.

## 4. Как создаются эмбеддинги — история и конвейер

- **Word2Vec (2013)** — учил векторы слов, предсказывая окружающий контекст (дистрибутивная гипотеза в действии). Не различал омонимы: «банк» — один вектор на все смыслы.
- **Современный конвейер:** токенизация → трансформер (BERT) выдаёт векторы токенов (hidden states) → **пулинг (pooling)** сворачивает их в один вектор на вход → часто **нормализация** вектора.
- **Sentence-BERT (2019)** — векторы предложений, напрямую сравнимые косинусным сходством. Поиск самой похожей пары: 65 часов (чистый BERT) → ~5 секунд.
- **CLIP** — кодировщик изображений + кодировщик текста обучены совместно → общее мультимодальное пространство → поиск картинок текстом.

### Конвейер векторизации (vectorization) своих данных

1. Собрать сырые данные.
2. Предобработка: токенизация, очистка, нормализация.
3. **Чанкинг (chunking):** текст → предложения/абзацы, изображения → патчи, ряды → окна.
4. Каждый чанк → модель эмбеддингов (обычно через API): OpenAI text-embedding-3, Cohere Embed, SentenceTransformers, GloVe; для картинок — VGG, CLIP.

```python
from openai import OpenAI
client = OpenAI(api_key="YOUR_API_KEY")
response = client.embeddings.create(
    model="text-embedding-3-small",      # 1536 измерений
    input="How to create vector embeddings using OpenAI",
    encoding_format="float"
)
embedding = response.data[0].embedding   # список из 1536 float
```
*(В актуальной версии библиотеки openai v1+ — обращение через точки: `response.data[0].embedding`, а не `response['data'][0]['embedding']`.)*

## 5. Метрики расстояния и сходства

Для векторов **a** и **b**:

| Метрика | Формула | Учитывает длину? | Где применяется |
|---|---|---|---|
| **Косинусное сходство (cosine similarity)** | cos(θ) = (a·b) / (‖a‖·‖b‖) | **Нет** — только угол | текстовые эмбеддинги, выбор по умолчанию |
| **Скалярное произведение (dot product)** | a·b = Σ aᵢbᵢ | **Да** | если длина несёт смысл или модель обучена под dot product |
| **Евклидово расстояние (Euclidean distance)** | d = √(Σ(aᵢ−bᵢ)²) | **Да** | пространственные данные, счётчики |
| **Манхэттенское расстояние (Manhattan distance)** | d = Σ\|aᵢ−bᵢ\| | Да | редко для текстов; разреженные данные («путь по кварталам») |

Обозначения: ‖a‖ = √(Σ aᵢ²) — норма (длина) вектора.

**Свойства косинусного сходства:**
- Диапазон [−1, 1] (для текстовых эмбеддингов обычно [0, 1]).
- **Результат > 1 или < −1 = ошибка в вычислении** (sanity check!).
- 1 = сонаправлены (одинаковый смысл), 0 = ортогональны, −1 = противоположны.
- Чем меньше угол между векторами, тем больше косинусное сходство, тем ближе смысл.
- **Шаблон: числитель — скалярное произведение, знаменатель — произведение норм.**

**Нормализация стирает различия между метриками:** если все векторы нормализованы до единичной длины, то косинусное сходство = скалярному произведению (нормы = 1), а евклидово расстояние — монотонная функция от него: d² = 2 − 2·cos. Порядок ближайших соседей одинаков при любой из трёх метрик.

### Пример расчёта (из источника №2)

«cat» = [1.2, 0.8], «dog» = [1.0, 0.9]:
- a·b = 1.2·1.0 + 0.8·0.9 = 1.92
- ‖a‖ = √(1.44 + 0.64) = √2.08 ≈ 1.442; ‖b‖ = √(1.0 + 0.81) = √1.81 ≈ 1.345
- cos = 1.92 / (1.442 · 1.345) ≈ **0.99** — почти сонаправлены, семантически близки ✅

## 6. Поиск по сходству (similarity search)

Задача: найти ближайшие к запросу векторы. Два решения — метрика (выше) и стратегия поиска.

- **Точный поиск k ближайших соседей (exact k-NN):** запрос сравнивается с каждым вектором. Гарантирует истинных соседей, но растёт линейно. Нормально для десятков тысяч векторов, больно на десятках миллионов.
- **Приближённый поиск (ANN, approximate nearest neighbor):** жертвует каплей точности ради скорости, строя индекс заранее.
  - **HNSW (Hierarchical Navigable Small World):** многослойный граф; верхние слои — грубые «шорткаты», нижние — уточнение. Плата: +память на связи графа; полнота (recall) зависит от данных и настройки.

## 7. Типы эмбеддингов

| Тип | Что кодирует | Применение |
|---|---|---|
| Словесные (word embeddings) | слова | синонимы, сходство, тональность |
| Предложений (sentence embeddings) | смысл фразы | чат-боты, поиск, категоризация |
| Документов (document embeddings) | общий смысл документа | рекомендации, кластеризация |
| Графов (graph embeddings) | узлы и рёбра | предсказание связей, сообщества |
| Изображений | визуальные признаки | поиск картинок (ResNet, VGG, CLIP) |
| Аудио | ритм, тон, высота | распознавание речи (Whisper) |
| Продуктов | товары, песни, фильмы | рекомендации |
| Молекул, 3D, временных рядов | химия, геометрия, временны́е паттерны | поиск лекарств, аномалии, прогнозы |

Градация для текста: **слово → предложение → документ** — одна идея на разных уровнях гранулярности.

## 8. Применения в продакшене

- **Семантический поиск (semantic search):** запрос естественным языком, не ключевые слова (Spotify: «cozy true crime»).
- **Рекомендации:** Airbnb, 32-мерные эмбеддинги на 800+ млн сессий → +21% CTR.
- **RAG (retrieval-augmented generation):** документы → чанки → эмбеддинги → ближайшие чанки подставляются в контекст LLM.
- **Семантический кэш (semantic caching):** повторные по смыслу вопросы → ответ из кэша без вызова LLM (~33% запросов к поисковикам повторяются).
- **Память агентов (agent memory):** релевантность воспоминания = косинусное сходство с текущим запросом (Stanford Generative Agents).

## 9. Хранение в масштабе

- **Векторные базы данных (vector databases)** — специализированные хранилища векторов. Альтернатива: PostgreSQL + расширение **pgvector** (векторы — колонка в обычной таблице рядом с метаданными).
- **Память:** плотные векторы «тяжёлые»; квантизация int8 уменьшает объём существенно (Redis заявляет до 75% — вендорские данные).
- **Индексы:** FLAT (точный, малые данные), HNSW (универсальный), SVS-VAMANA (большие масштабы + компрессия).
- **Фильтрованный поиск:** вектор + метаданные («похожие документы за 30 дней»). **Гибридный поиск (hybrid search):** ключевые слова + векторное сходство.
- ⚠️ Числа вендоров (75% памяти, −73% стоимости LLM, 15× кэш) — маркетинговые claims, не независимые измерения.

## 10. Ключевые формулировки для контрольной точки

> **Эмбеддинг** — это перенос данных (текста, картинки) из высокоразмерного пространства в компактный плотный вектор чисел; при этом теряется форма (стиль, конкретные слова, длина) и сохраняется смысл. Модель обучается на задаче (предсказать контекст, сравнить похожесть): случайные векторы подкручиваются обратным распространением ошибки, и тексты, взаимозаменимые для задачи, оказываются рядом в пространстве.
>
> **Косинусное сходство** — косинус угла между двумя векторами: скалярное произведение, делённое на произведение длин. Оно игнорирует длину векторов и смотрит только на направление: ближе к 1 — смысл совпадает, ближе к 0 — не связан. Поэтому «я забыл пароль» и «как сбросить вход» находят друг друга без общих слов — сравнивается не текст, а положение в векторном пространстве.

## 11. Практика (задание из плана)

### Шаблон: косинусное сходство руками (numpy, без библиотек ML)

```python
import numpy as np

a = np.array([1.0, 2.0, 3.0])
b = np.array([2.0, 4.0, 6.0])   # сонаправлен с a → жди cos = 1.0

dot = np.dot(a, b)              # скалярное произведение
norm_a = np.linalg.norm(a)      # норма (длина)
norm_b = np.linalg.norm(b)
cos_sim = dot / (norm_a * norm_b)
print(cos_sim)
```

Проверочные пары: b = [−1, −2, −3] → жди −1.0; b = [3, −2, 1] → посчитай руками, сверь с кодом.

### 3 пары фраз (придумать самому)

1. Близкие по смыслу (разные слова) — ожидание: cos близко к 1.
2. Разные по смыслу — ожидание: cos ближе к 0.
3. Похожие по словам, разные по смыслу («банк реки» / «банк денег») — проверка, различает ли модель омонимы по контексту (Word2Vec — нет, Sentence-BERT и новее — да).

## 12. Ошибки и поправки из самопроверок (не повторять!)

1. **Косинус ИГНОРИРУЕТ длину вектора** (смотрит только угол). Длину учитывают евклидово расстояние и скалярное произведение.
2. **Шаблон формулы:** скалярное произведение — в числителе, произведение норм — в знаменателе. Результат обязан быть в [−1, 1].
3. **Re-training меняет модель, re-embedding меняет данные.** Прогон новых документов через старую модель — не re-training.
4. Несравнимость векторов разных моделей — не про «обрезанные размерности», а про **разные системы координат** (пространства).
5. Дистрибутивная гипотеза — утверждение о языке (контексты ↔ значения); «похожие векторы» — следствие, а не сама гипотеза.
6. One-hot (унитарный код) ≠ one-shot (обучение по одному примеру) — разные термины.
7. «Косинус угла ближе к 1» (не «угол ближе к 1»); сам угол при этом ближе к 0°.
