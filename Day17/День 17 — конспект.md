# День 17 — Визуализация эмбеддингов: t-SNE / UMAP

## Источники

1. **OpenAI Cookbook — Visualizing embeddings in 2D** — минимальный рецепт: эмбеддинги (1536 измерений, 1000 отзывов Amazon) → t-SNE (perplexity=15) → scatter-plot с раскраской по метаданным (оценка в звёздах). Результат: разделение данных видно даже в 2D.
2. **Nomic — How to Visualize Embeddings with t-SNE, UMAP, and Nomic Atlas** — обзорный гид: зачем визуализировать, сравнение t-SNE / UMAP / Atlas, best practices и типичные ошибки.

## Ключевые понятия

- **Эмбеддинг (embedding)** — плотный вектор текста; похожие по смыслу тексты лежат близко в пространстве. Типичные размерности: 1536 (`text-embedding-3-small`), 3072 (`text-embedding-3-large`).
- **Снижение размерности (dimensionality reduction)** — проекция в 2D для визуализации; теряем информацию, стараемся сохранить *соседство*.
- **t-SNE (t-Distributed Stochastic Neighbor Embedding)** — оптимизирует **локальные соседства**, жертвуя глобальной геометрией. Поэтому расстояния *между* кластерами и их размеры на графике **неинтерпретируемы**. Медленный (~O(N log N), Barnes-Hut в sklearn), для малых/средних датасетов.
- **UMAP (Uniform Manifold Approximation and Projection)** — быстрее, сохраняет локальную и *частично* глобальную структуру; реже разрывает один кластер на куски.

## Параметры

| Параметр | Метод | За что отвечает | Эффект увеличения |
|---|---|---|---|
| perplexity | t-SNE | сколько соседей «видит» точка | кластеры крупнее и слитнее; типично 5–50, строго < числа точек |
| n_neighbors | UMAP | аналог perplexity | глобальнее картина, локальные различия стираются |
| min_dist | UMAP | плотность упаковки точек в 2D | больше → рыхлее и равномернее (0.0 — тугие комки, 0.5 — облако); визуальный параметр, на состав кластеров не влияет |
| metric | UMAP | метрика расстояния | для текста — `cosine`: смысл закодирован в направлении вектора, косинус игнорирует длину; согласовано с метрикой поиска в RAG |
| random_state | оба | воспроизводимость | фиксирует случайность |

## Правила интерпретации

1. Кластеры на графике — значимы; расстояния между кластерами и их размеры — нет (t-SNE), частично (UMAP).
2. **Compare multiple methods**: кластер, видимый и в t-SNE, и в UMAP, — настоящий; видимый только в одном методе — возможно, артефакт.
3. Всегда раскрашивать по известным метаданным (темы) — это превращает график в диагностику.
4. Точки-«предатели» (чужой цвет внутри кластера) — ценные находки: ошибка разметки, пересечение тем или текст, который модель не понимает.
5. Точное сходство тем проверяется косинусной метрикой на исходных эмбеддингах, а не на 2D-проекции.

## Диагностика «нет кластеров» — порядок проверки

1. Параметры проекции (perplexity / n_neighbors не соответствуют размеру датасета).
2. Данные (тексты слишком короткие/однотипные, темы реально пересекаются).
3. Только потом — вывод о качестве эмбеддинг-модели.

**Контрольная точка дня:** визуализация — диагностика *до* сборки RAG: если кластеров нет, поиск будет тащить нерелевантные документы.

## Практика: что сделано

- Датасет: 40 текстов, 4 темы (спорт, кулинария, технологии, финансы) × 10, разные стили и длины.
- Эмбеддинги: `text-embedding-3-small`, один батчевый вызов API, кэш в `embeddings.npy` (не запрашивать API на каждый прогон!).
- t-SNE: perplexity 5/10/15/20; UMAP: n_neighbors 5/30 × min_dist 0.0/0.5, `metric='cosine'`.

## Результаты экспериментов

- **perplexity=5** → темы дробятся на мелкие островки (только локальная микроструктура).
- **perplexity=10–15** → самые читаемые 4 кластера (оптимум для 40 текстов).
- **perplexity=20** → кластеры видны, но рыхлее; почти потолок для такого датасета.
- **n_neighbors=5, min_dist=0.0** → тугие далёкие комки; **min_dist=0.5** → те же группы равномернее.
- **n_neighbors=30** (≈75% датасета) → «спорт» и «технологии» размыты и сближены, локальные различия стёрты.
- **Главное:** при всех разумных настройках обоих методов 4 темы разделяются → структура — свойство данных, эмбеддинг-модель темы улавливает.

## Ловушки, встреченные на практике

- Кэш не проверяет, изменились ли исходные тексты — старый `.npy` подставится молча.
- Эмбеддинги OpenAI имеют микронедетерминированность; t-SNE с `init='random'` чувствителен к ней — раскладка шатается, кластерная структура устойчива.
- `literal_eval` нужен только если эмбеддинги хранятся строкой в CSV; из API приходят списки сразу.

## Шпаргалка по коду

```python
# Эмбеддинги с кэшем
if os.path.exists("embeddings.npy"):
    matrix = np.load("embeddings.npy")
else:
    response = client.embeddings.create(model="text-embedding-3-small", input=texts)
    matrix = np.array([item.embedding for item in response.data])
    np.save("embeddings.npy", matrix)

# t-SNE
from sklearn.manifold import TSNE
vis = TSNE(n_components=2, perplexity=15, random_state=42,
           init='random', learning_rate=200).fit_transform(matrix)

# UMAP
import umap
vis = umap.UMAP(n_neighbors=10, min_dist=0.1, metric='cosine',
                random_state=42, n_jobs=1).fit_transform(matrix)
```
