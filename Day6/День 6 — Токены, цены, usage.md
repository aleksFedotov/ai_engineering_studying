# День 6 — Токены, цены, usage

Конспект по разбору официальных страниц цен OpenAI и Anthropic (август 2026) и коду расчёта стоимости вызовов.

---

## 1. Базовый принцип тарификации

- Все цены — **за 1 миллион токенов** (у Anthropic обозначение «MTok»), оплата только за фактическое использование, без абонентской платы.
- Тарификация раздельная по направлению:
  - **Input** — токены запроса (промпт, системная инструкция, контекст);
  - **Output** — токены ответа модели;
  - **Cached input** — токены, прочитанные из prompt cache (в 10 раз дешевле input);
  - **Cache writes** — запись в кэш (премиальная цена, ~1.25–2× от input).
- **1 токен ≈ 0.75 английского слова ≈ 4 символа**. Для русского текста токенов на тот же объём выходит заметно больше — проверять токенизатором.

## 2. Цены OpenAI (Standard, короткий контекст, $/1M токенов)

| Модель | Input | Cached input | Cache writes | Output | Ниша |
|---|---|---|---|---|---|
| **GPT-5.6 Sol** | $5.00 | $0.50 | $6.25 | $30.00 | флагман |
| **GPT-5.6 Terra** | $2.00 | $0.20 | $2.50 | $12.00 | продакшн-дефолт |
| **GPT-5.6 Luna** | $0.20 | $0.02 | $0.25 | $1.20 | массовые задачи, классификация |

Особенности:
- **Длинный контекст** (свыше ~272K входных токенов): цены растут до 2× на input и 1.5× на output — причём повышенная ставка применяется ко **всему** запросу целиком.
- **Уровни обслуживания**: Standard (база), Batch API (−50%, результат в течение 24 ч), Flex (−50%, медленнее), Fast mode (бывший Priority, ~2× дороже).
- **Prompt caching автоматический**: повторяющийся префикс промпта тарифицируется по цене cached input (10% от обычной), отдельной команды не требуется.
- Reasoning-модели: внутренние «мысли» (`reasoning_tokens`) входят в `completion_tokens` и оплачиваются по цене output — реальный счёт может быть в 3–10 раз выше наивной оценки по видимому ответу.
- Прочее: embeddings только по input (text-embedding-3-small $0.02/1M); web search $10/1000 вызовов; видео Sora — за секунду (720p $0.10/с, 1080p pro $0.70/с); транскрибация — за минуту (от $0.003/мин).

## 3. Цены Anthropic (Claude, $/1M токенов)

| Модель | Input | Cache write (5 мин) | Cache write (1 час) | Cache read | Output | Ниша |
|---|---|---|---|---|---|---|
| **Claude Fable 5** | $10 | $12.50 | $20 | $1 | $50 | верхний тир |
| **Claude Opus 5** | $5 | $6.25 | $10 | $0.50 | $25 | сложное кодирование, агенты |
| **Claude Sonnet 5** | $2 | $2.50 | $4 | $0.20 | $10 | основная рабочая лошадка |
| **Claude Haiku 4.5** | $1 | $1.25 | $2 | $0.10 | $5 | быстрые дешёвые задачи |

Особенности:
- **Prompt caching явный**: включается полем `cache_control` (автоматический режим или ручные точки). Запись стоит 1.25× input (кэш живёт 5 минут) или 2× (1 час); чтение — 0.1×. Окупаемость: со **второго** чтения для 5-минутного кэша, с третьего — для часового.
- **Длинный контекст без надбавки**: окно 1M токенов по стандартной цене (запрос на 900K токенов стоит за токен столько же, сколько на 9K).
- **Batch API**: −50% на input и output; комбинируется с кэшированием.
- **Fast mode** (только Opus 5/4.8): $10/$50 — ровно 2× от стандарта, несовместим с Batch.
- **Data residency** (`inference_geo: "us"`): множитель 1.1× на все категории токенов.
- **Накладные расходы tool use**: включение инструментов добавляет системный промпт ~300–800 токенов; bash +244–325; text editor +700; computer use ~4500; **browser use ~6600 input-токенов на каждый запрос**. Web search $10/1000 поисков; web fetch бесплатен (платим только за токены контента: средняя страница ~2500 токенов, PDF-статья ~125 000).

## 5. Формула стоимости запроса

```
cost = (входные_токены × цена_input
      + кэшированные_токены × цена_cached
      + записанные_в_кэш × цена_cache_write   # только Anthropic
      + выходные_токены × цена_output) / 1_000_000
```

Без кэша вырождается в базовую формулу из отчёта:
`(входные / 1M × цена_входа) + (выходные / 1M × цена_выхода)`.

### Ловушки при чтении поля `usage`

1. **OpenAI**: `cached_tokens` уже **включены** в `prompt_tokens` → свежий input = `prompt_tokens − cached_tokens`. Не вычесть — посчитаешь кэш дважды.
2. **Anthropic**: `input_tokens` — только свежие токены; кэш лежит отдельно в `cache_read_input_tokens` и `cache_creation_input_tokens` → их нужно **прибавить**, каждое по своей цене.
3. `reasoning_tokens` уже входят в output — отдельно платить не нужно, но именно они раздувают счёт у «думающих» моделей.

Структуры ответов:

```json
// OpenAI
"usage": {
  "prompt_tokens": 1500,
  "completion_tokens": 400,
  "total_tokens": 1900,
  "prompt_tokens_details": { "cached_tokens": 1200 },
  "completion_tokens_details": { "reasoning_tokens": 150 }
}

// Anthropic
"usage": {
  "input_tokens": 300,
  "output_tokens": 400,
  "cache_creation_input_tokens": 0,
  "cache_read_input_tokens": 1200
}
```

## 6. Код: калькулятор стоимости вызова

```python
# Цены в USD за 1 токен (из официальных страниц цен, август 2026)
PRICES = {
    # OpenAI
    "gpt-5.6-sol":    {"input": 5.00e-6,  "cached": 0.50e-6,  "output": 30.00e-6},
    "gpt-5.6-terra":  {"input": 2.00e-6,  "cached": 0.20e-6,  "output": 12.00e-6},
    "gpt-5.6-luna":   {"input": 0.20e-6,  "cached": 0.02e-6,  "output": 1.20e-6},
    # Anthropic
    "claude-fable-5":  {"input": 10.0e-6, "cached": 1.00e-6, "cache_write": 12.50e-6, "output": 50.00e-6},
    "claude-opus-5":   {"input": 5.00e-6, "cached": 0.50e-6, "cache_write": 6.25e-6,  "output": 25.00e-6},
    "claude-sonnet-5": {"input": 2.00e-6, "cached": 0.20e-6, "cache_write": 2.50e-6,  "output": 10.00e-6},
    "claude-haiku-4.5":{"input": 1.00e-6, "cached": 0.10e-6, "cache_write": 1.25e-6,  "output": 5.00e-6},
}

def cost_openai(model: str, usage: dict) -> float:
    """Стоимость вызова OpenAI по объекту usage из ответа."""
    p = PRICES[model]
    cached = usage.get("prompt_tokens_details", {}).get("cached_tokens", 0)
    fresh_input = usage["prompt_tokens"] - cached   # cached уже внутри prompt_tokens!
    return fresh_input * p["input"] + cached * p["cached"] + usage["completion_tokens"] * p["output"]

def cost_anthropic(model: str, usage: dict) -> float:
    """Стоимость вызова Anthropic по объекту usage из ответа."""
    p = PRICES[model]
    return (usage["input_tokens"] * p["input"]
            + usage.get("cache_read_input_tokens", 0) * p["cached"]
            + usage.get("cache_creation_input_tokens", 0) * p.get("cache_write", p["input"])
            + usage["output_tokens"] * p["output"])
```

## 8. Теория: почему output дороже input в 4–6 раз

- **Input обрабатывается параллельно**: весь промпт проходит через GPU одной пачкой (prefill — одна большая матричная операция, железо загружено эффективно).
- **Output генерируется последовательно, токен за токеном**: каждый новый токен — полный прогон модели с неэффективной утилизацией GPU (batch size = 1 на пользователя). 400 токенов ответа = 400 прогонов.
- Пока модель генерирует, память под KV-кэш занята, а пользователь ждёт в реальном времени — провайдер закладывает в цену latency и упущенную утилизацию.

**Prompt caching** — сохранение KV-кэша (внутреннего состояния модели после обработки начала промпта). Повторяющееся начало не пересчитывается → чтение из кэша в 10 раз дешевле, потому что это чтение из памяти вместо вычислений.

## 9. Контрольная точка ✔

Прикидка в уме: запрос 1500/400 на флагмане Sol —
- input: 1500 × $5/1M ≈ $0.0075
- output: 400 × $30/1M ≈ $0.012
- итого ≈ 2 цента → **1000 запросов ≈ $20** (точный расчёт: $19.50 ✔)

Заметка: output даёт ~60% стоимости, хотя его токенов в 3.75 раза меньше, чем input. Длинные ответы — главный источник расходов, а не длинные промпты.
