# Обработка ошибок API

Что падает в реальной жизни (из семинара и моего опыта):

1. 401 Unauthorized — неверный или отозванный API-ключ. Лечение: проверить ключ, переменную окружения. Ретраить бессмысленно.
2. 429 Rate Limit — превышен лимит запросов/токенов в минуту ИЛИ кончились деньги (insufficient_quota тоже 429, это путало!). Лечение: exponential backoff.
3. 500/503 — проблемы на стороне OpenAI. Лечение: ретрай с паузой.
4. Таймауты и обрывы соединения — особенно актуально при стриминге: поток может оборваться посередине.
5. context_length_exceeded — не влезли в контекст. Лечение: обрезать историю или документы.

Паттерн exponential backoff: пауза 1с → 2с → 4с → 8с, обычно 3–5 попыток, плюс случайный jitter, чтобы клиенты не «толпились».

Важный принцип с лекции: ретраим только временные ошибки (429, 5xx, таймауты). Перманентные (401, 400 — кривой запрос) ретраить бессмысленно и вредно.

Моя заметка: в мини-проекте минимум — try/except вокруг запроса с понятным сообщением пользователю на русском, а не сырым traceback. Пользователь чата — это я сам, но привычка правильная.
