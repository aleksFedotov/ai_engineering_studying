# RAG (Retrieval-Augmented Generation)

RAG — паттерн, когда модели в контекст подкладывают найденные документы, и она отвечает на их основе.

Пайплайн с лекции:
1. Индексация (офлайн): документы → чанки → эмбеддинги → векторная БД.
2. Поиск (онлайн): вопрос → эмбеддинг вопроса → top-k ближайших чанков.
3. Генерация: системный промпт + найденные чанки + вопрос → ответ.

Зачем RAG, если есть длинный контекст:
- Дешевле: не тащить гигабайты текста в каждый запрос.
- Точнее: меньше шума, меньше lost in the middle.
- Свежие данные без переобучения модели.

Типичные проблемы (из разбора в семинаре):
- Плохой чанкинг: разрезали предложение посередине.
- Поиск нашёл «похожее, но не то» — модель честно ответит по нерелевантному куску.
- Модель всё равно додумывает — лечится промптом «отвечай только по контексту».

Моя заметка: наш мини-проект — это RAG без retrieval, т.е. просто «G». Retrieval заменён на ручную подгрузку всех заметок. Это нормальный первый шаг.
