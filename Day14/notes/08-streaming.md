# Стриминг

Стриминг — API отдаёт ответ по кусочкам (чанкам), а не целиком в конце. В OpenAI API включается параметром stream=True.

Зачем:
- UX: пользователь видит текст сразу, как в ChatGPT. Для длинных ответов разница ощутимая: время до первого токена ~1 сек против ~10 сек ожидания всего ответа.
- Можно прервать генерацию на лету.

Технически: ответ приходит как поток событий. Каждый чанк содержит delta — кусочек нового текста. Полный ответ собирается конкатенацией всех delta.content.

Подводные камни из семинара:
- Поле usage (счётчик токенов) в стриминге по умолчанию НЕ приходит. Нужно передавать stream_options={"include_usage": True} — тогда usage придёт в самом последнем чанке, где choices пустые.
- Первый чанк обычно содержит только роль (role: assistant), без текста.
- Если стримить без аккумуляции, потом не сможешь посчитать стоимость и сохранить ответ в историю.

Моя заметка: для мини-проекта сначала сделать БЕЗ стриминга, убедиться что всё работает, потом добавить. Отладка стриминга с нуля — боль.
